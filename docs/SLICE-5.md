# Slice 5 — Dedicated browser

The native supervisor owns a separate Node Browser Manager with its own Windows Job Object. Pi's stdin/stdout transport only requests operations; it never launches Chromium. Closing the interface leaves the native tray host and browser running. Pi hibernation, restart and generation cancellation do not terminate the browser service. Stop in the chat browser closes that thread's tabs. Stopping the browser service closes Chromium without deleting its profile. Quit Talo shuts down services, including Chromium, and the Job Object removes descendants if graceful shutdown fails or the host crashes.

Playwright is the sole Chromium launcher. Chromium now runs headlessly and renders its actual page inside Talo through a private CDP screencast; it opens no separate Chrome window or tab strip. The existing packaging pipeline bundles the Chromium revision pinned by Playwright 1.64.1 and records it in `vendor/runtime-manifest.json`. Stagehand 4.3.0 attaches to that browser; it never launches another one or uses Browserbase. Chromium's sandbox is explicitly enabled. Stagehand's extension is shipped inside its npm package. Only that extension's computed origin is allowed on the loopback CDP connection. The manager API is the host-owned stdio pipe, not a public HTTP server. As with other desktop browser automation, processes running as the same Windows user remain inside the local trust boundary.

The persistent primary profile is `browser/profiles/primary` under Talo's application data directory. An existing Slice 1–4 `browser-profile` is migrated once. A process lock prevents two managers from using the same profile. Crash recovery reaps the service's complete process tree before relaunching it. Profile directories are independent of Pi sessions and memory. Each chat has a session keyed by its host-owned conversation ID, with independent tabs, automation queues and human-control ownership. All chat sessions share the primary Chromium context and its website logins, as requested. Sessions are not cookie or account isolation boundaries. The browser service launches Chromium once. Deleting a chat or workspace releases its browser tabs; quitting closes all sessions. Sub-agent execution is not implemented.

## Tools and permissions

Pi registers `browser_open`, `browser_tabs`, `browser_snapshot`, `browser_interact`, `browser_ai`, `browser_screenshot`, `browser_download` and `browser_handoff`. DonSeTch's four `web_*` research tools remain separate. Browser activity appears in chat without typed values, extracted page data or credentials in activity previews.

Browser actions and downloads run automatically without per-action approval prompts, following the user's explicit configuration request. The host validates the chat thread, supplies authorization and ignores model-supplied target overrides. Tool enable/disable settings still apply. Take Over and Stop retain exclusive ownership and cancellation. Uploads and password entry use manual takeover. Website content is explicitly untrusted; there is no automatic write into permanent memory.

Supported native Stagehand providers use the current connection's key and model. OpenAI-compatible providers, including OpenCode, OpenRouter and configured compatible custom endpoints, use Stagehand's client-side model callback with the same connection. Incompatible custom APIs fail explicitly; there is no cloud fallback. Logging and caching are disabled for Stagehand. Credentials are only passed over private host pipes and kept in process memory; errors exclude provider response bodies and keys. No cookie, storage or arbitrary JavaScript tools are exposed. Accessible snapshots omit form values; screenshots remain private artifacts and should not be requested on credential screens.

All browser HTTP(S) traffic uses a local egress proxy that resolves and validates destination addresses before connecting to the selected IP. Private, loopback and custom-port destinations are denied, including redirects and subresources. Page requests to loopback are additionally blocked by Playwright routes; the Stagehand extension alone needs the loopback CDP exception. Page WebSockets and service workers are blocked in V1; some sites that depend on them may require future compatibility work. QUIC and non-proxied WebRTC UDP are disabled. Agent navigation only accepts public HTTP(S) URLs.

Chromium's automatic downloads are denied. `browser_download` accepts a public URL automatically, uses matching profile cookies privately, pins the resolved address, rejects redirects, limits files to 25 MiB and writes a unique non-executable `.download` file into `browser/downloads`. Neither websites nor the model choose an arbitrary output path. Files are never automatically opened or executed.

## In-app view, ownership and cancellation

The composer has a Browser chip. A small card alongside chat shows the current page and background activity; Pi never forces the large view open. The selected chat automatically starts a live thumbnail when its browser connects. The Browser chip can reopen a hidden preview. Clicking the card opens a large page inside Talo. The Browser navigation page offers the same viewer. There is no embedded third-party iframe and no external Chrome window.

Opening either view preserves the current owner: watching Pi does not interrupt it. Take Over first cancels pending automation, then enables the live page's pointer, keyboard, scrolling, paste and address controls. Return Control drains pending manual input before Pi can act again. Input forwarding is a private host UI method, separate from Pi's tools, with checks for human ownership, a viewer lease and the current tab. Pi cannot grant itself manual control or use the forwarding path. Pause and Stop live inside the viewer instead of above the conversation.

Frames are JPEGs generated by CDP `Page.startScreencast`, not periodic tool screenshots. They are bounded, throttled to at most ten per second, kept only as the newest frame in host memory, and sent only to the main app view. They are never saved, logged, attached to chat or passed to a model. Frames are requested automatically for the visible chat only, tagged with its session ID, and rejected by the UI if they belong to another chat. Expanding the browser preserves that stream; hidden chats do not stream. Closing or hiding the interface stops the stream; an eight-second viewer lease also cleans up a lost WebView. Chromium and its profile remain running. Minimizing the large view returns to the thumbnail. Leaving or hiding the chat during manual takeover leaves its automation paused.

The page viewport is 1280 by 800; the viewer scales coordinates to match it. Native Chrome UI, OS file pickers and extension popups are not mirrored. Existing upload restrictions remain in place. This is an interactive Chromium page surface, rather than a complete reproduction of Chrome's desktop UI.

Browser and research actions appear as one collapsed activity group per assistant turn. Only expanding the group reveals individual calls, sources, errors and saved artifacts. The preview and composer chip are independent of that group.

Operations are serialized within each chat session, have cancellation and deadlines, and are bound to the worker epoch. A cancelled or timed-out in-flight operation closes its active tab so queued Playwright or Stagehand commands cannot continue after takeover. This conservative interruption may discard unsaved work in that tab; cookies and the profile remain. Other tabs are retained. Browser crashes leave an explicit error state and can be recovered by opening the browser again.

The page rendering and input bridge use the official [CDP Page](https://chromedevtools.github.io/devtools-protocol/tot/Page/) and [CDP Input](https://chromedevtools.github.io/devtools-protocol/tot/Input/) APIs.

## Verification

The existing check/build commands cover the UI, TypeScript workers and native host. Browser integration coverage exercises bundled sandboxed Chromium, profile persistence, deterministic interaction, stale approvals, ownership, cancellation, crash recovery and local Stagehand extraction through a fixture provider. The service lifecycle check exercises Pi sleep/wake independence without a native window helper. It does not use a live paid provider.

Completed during implementation: worker compilation, UI production build, browser integration checks, local Stagehand extraction, bundled runtime verification and the service sleep/wake check. The embedded-view rework additionally received a focused runtime check of frame delivery, watch ownership, manual pointer/text input, return-control rejection of manual input, and Chromium survival after closing the viewer. A real paid-provider call and a signed installer were not exercised.

The right-hand companion uses the animated Talo logo for working, resting, starting, browser ownership and error status. The separate Pi status badge has been removed from the conversation header. The browser card includes live page title/URL and Take Over, Return Control and Stop. A focused two-thread runtime smoke verified independent tabs and actions, shared persistent cookies, independent takeover/stop and session-tagged frame delivery without saving screenshots.
